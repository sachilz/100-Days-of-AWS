Welcome to my central repository for tracking my journey through the **KodeKloud 100 Days of AWS** challenge! 🚀

This challenge is designed to build strong, hands-on cloud skills over 50 action-packed days. Throughout this journey, I'll be exploring everything from fundamental compute and storage services to networking, security, databases, and architectural best practices in Amazon Web Services.

---

## 🎯 Repository Goals
1. **Consistency & Accountability**: Track daily progress and ensure continuous learning.
2. **Knowledge Base**: Act as a personal reference wiki for AWS configurations, CLI commands, and troubleshooting.
3. **Hands-on Proof**: Showcase practical, working implementations rather than just theory.

---

## 📂 Repository Structure

To keep the 50 days of tasks organized, the repository is split into 5 structured phases. Each phase contains 10 days of continuous learning.

- 📁 **[Days_01-10](./Days_01-10)**: Phase 1 - (Tasks 1 to 10)
- 📁 **[Days_11-20](./Days_11-20)**: Phase 2 - (Tasks 11 to 20)
- 📁 **[Days_21-30](./Days_21-30)**: Phase 3 - (Tasks 21 to 30)
- 📁 **[Days_31-40](./Days_31-40)**: Phase 4 - (Tasks 31 to 40)
- 📁 **[Days_41-50](./Days_41-50)**: Phase 5 - (Tasks 41 to 50)

*(Note: You can navigate into any folder to see the specific themes covered in that 10-day block).*

### 📁 Inside Each Day's Folder
Inside every day folder (e.g., `Day_01`, `Day_02`), you can expect to find:
- **The Question / Task**: A clear outline of the scenario or problem provided by KodeKloud for that day.
- **My Answer / Solution**: My approach to solving the task, which may include:
  - Step-by-step configuration instructions (using the AWS Management Console).
  - Terminal logs and **AWS CLI** commands used.
  - Explanations of *why* a certain configuration was chosen.
  - Verification screenshots or testing commands to prove the setup works.

## 🛠️ Core Topics Explored
During this course, I will be working hands-on with a wide variety of AWS services, including but not limited to:
- **Compute**: EC2, Auto Scaling Groups, Elastic Load Balancing (ELB)
- **Storage**: S3, EBS, EFS
- **Networking**: VPC, Subnets, Route Tables, Internet/NAT Gateways, Route 53
- **Security & Identity**: IAM (Users, Roles, Policies), Security Groups, Network ACLs
- **Databases**: RDS, DynamoDB
- **Monitoring & Management**: CloudWatch, AWS Auto Scaling
